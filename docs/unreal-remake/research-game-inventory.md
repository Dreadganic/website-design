## 3. How tangled the rules are
Formulas are separable; state changes are not. About 630 of the 970 functions (a regex estimate) touch neither DOM, canvas nor sound: small formulas over one global save object `S` (`cupFor`, `saleFor` L6694-6704) that port almost line for line. Most functions that change state also play sound, raise notices or build HTML.
- `tickFarm` (L2609-2652): income comes from pickers walking at 24 px/s between bush coordinates stored in `sprites.json`, so the map layout is a balance input.
- `sellLot` (L6720-6738): payout, stats and task counters, then `SFX.play`, `toast` and a `showModal` HTML string in one function. `levelUp` (L6610) and `prestige` (L6889) are alike.
- `tick(dt)` (L2683-2727) is the nearest thing to a state update, but it toggles DOM elements and spawns particles. Events, the counter and the islands tick separately in `loop` (L8900), and the islands read the wall clock.

One useful seam: every player action arrives as a `data-act` string through one click listener (L7989-8254, about 219 verbs).

The pacing bot runs the real page; no headless rules model exists. `sim/run.js` opens a patched build in Playwright Chromium with a fake clock; `sim/policy.js` calls `tick(0.25)` in a loop at about 700× speed, acts by clicking hidden `data-act` buttons, and calls `away(7.8)` between casual sessions. It never runs events, the counter or the islands.

## 4. Art

`game-assets/bg/` holds 68 PNGs: 26 top-down pixel-art scenes at 192 × 352 (14 farm scenes by season, the mill, 5 roastery interiors, the harbour, 5 islands) and 42 estate-stage overlays from 60 × 37 to 117 × 85. The game draws on a 192 × 352 canvas shown at 2×.

Drawn in code, not stored: the prestige 7-10 barns, racks and roasters (`drawBarn` L2165, `drawRack` L2239, `drawRoaster` L2273: about 180 rectangle calls, no sprites), farm effects (`drawFx` L1000), weather, fireworks, and the moving parts of each island scene (`drawKona` L4568). The interface is HTML and CSS.

## 5. Audio
Everything is synthesised live with the Web Audio API. There are no audio files and no offline renderer, so all of it must be rendered for another engine.
- Effects: 59 one-shots (`sfx.js` 33, `shop-sfx.js` 12, `kona-sfx.js` 14), with random pitch and timing per play.
- Events (`event-sfx.js`): 10 events, each with a start sting, a loop, 2 to 4 tap sounds, a clear and rare variants.
- Music: 14 songs in `music.js` (four-channel chiptune), each re-voiced in `cozy.js`, with night variants.

## 6. Server
| Handler (`netlify/lib/handlers/`) | Does |
|---|---|
| `game-account` | creates or deletes an anonymous player |
| `game-save` | cloud save, version-checked |
| `game-score` | leaderboards and the plausibility check |
| `game-name`, `game-link` | unique names; one-time code to move a farm to another device |
| `game-coop` | co-ops, weekly order, stickers, help, Derby, projects |
| `game-harvest`, `game-coe` | Harvest Day goal; Cup of Excellence, scored on the server |
| `game-visit` | farm snapshots and Cheers |
| `game-checkin`, `game-samples` | check-ins and free-sample eligibility |
| `game-claim`, `game-grants`, `game-gift` | paid orders into cranes, pending rewards, gift codes |
| `game-events` | drop events from a JSON file |
| `game-beacon`, `game-stats`, `game-admin` | analytics in, stats out, admin tools |
| `create-checkout`, `get-order`, `stripe-webhook` | the shop |

- Accounts are anonymous: the server issues an id and a secret token once, keeps only a hash, and the client sends `Authorization: Bearer <id>.<token>` (`authed`, `netlify/lib/game.js` L43).
- The server never simulates the game. `checkScore` (`game.js` L90) refuses progress faster than fixed rates allow; looks, names and visit snapshots are whitelisted; co-op and Harvest contributions are rate-capped. A save is checked only for size (400 KB), version and finite numbers.
- Storage is Netlify Blobs, one store, about 20 key prefixes.
- A native client can call these as they are: JSON over HTTPS, no cookies, no origin checks. But the cloud save is the web client's `S` object, so shared saves mean a shared schema, and the server's copies of game constants and cosmetic ids must stay in step.

## 7. Save data
- Local: `localStorage['beju-farm-save-v3']` (L2040), the whole `S` object as JSON every 5 s.
- `fresh()` (L2378) has 70 top-level fields; about 213 distinct `S.<field>` names appear, because features add sub-objects later. Every bush and picker position is saved.
- Cloud save: yes, the same JSON, at most every 5 minutes (`cloudSync` L8392), with a "newer save found" choice.
- Migrations: one `migrate()` (L2391-2431) on every load fills missing fields from `fresh()` and applies one-off conversions. There is no version ladder; the `v: 1` field is never read.
