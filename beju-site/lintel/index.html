  • Activation stays available in Settings, before and after purchase
  • Keys work offline, on any Mac, forever — no re-activation dance
  • Deactivating frees the seat without burning the key
  • Every failure message tells the customer what to actually do

Three lines, not three weeks

You write the product.

Drop the public key in one file, apply the gate to your root view, and the app knows whether it is paid for. Everything else is already there.

Keys are bound to your bundle identifier, so one leaked key can't unlock your other apps. Expiry travels inside the signature — the app enforces it without ever asking a server. 

// 1. Point at your checkout
enum LicenseConfiguration {
    static let productID = "com.yourname.app"
    static let publicKeyBase64 =
        "YLOixM5lRd7qwRF//…"
    static let trialDays = 14
}

// 2. Gate the app
@main struct YourApp: App {
    var body: some Scene {
        Window("YourApp", id: "main") {
            RootView()
                .licenseGate()      // paywall when it expires
                .environment(LicenseStore.shared)
        }
    }
}

Questions

The things you'd ask before paying.

Does this work with the Mac App Store?

The shell, settings window and design system do. The licensing layer is built for selling directly — the App Store handles payment itself, so you'd disable the gate and keep everything else. Both entitlement files ship: hardened runtime for direct distribution, sandbox for the store.

Do I need a server or a database?

No. Keys are signed with your private key and verified in the app with your public key, so there is nothing to host and nothing to go down. You can optionally mint keys from a payment webhook — the CLI emits JSON for that — but the app never talks to it.

What happens if someone shares a key?

Key sharing exists in every offline scheme, including the big ones. Lintel's answer is proportionate: keys are bound to your bundle identifier, seat counts travel in the key, and the docs include the two cheap mitigations that actually work (per-order keys and an optional online check on high-value tiers). No scheme makes a Mac app uncrackable, and a paywall that punishes paying customers costs more than piracy.

Which macOS versions are supported?

Deployment target is macOS 14 Sonoma. The kit is developed and tested on macOS 26 and 27, with availability checks where newer APIs are used — the glass scroll-edge treatment and the sidebar toggle removal are both guarded.

Can I use it for client work?

Yes. Ship it in as many apps as you like, including work you're paid to build for someone else. The only restriction is redistributing the kit itself as a template or starter product.

What do I actually receive?

A git repository: the Xcode project and Swift sources, the licensing CLI, the release scripts, the icon generator, the demo app, and the docs — including the launch playbook that covers pricing, where to post, and what to write. Download link arrives immediately after payment.
